2. Variables: DECLARE, SET, SELECT

A local variable is a named place to store one value while a T-SQL batch, stored procedure, or function is running. Its name starts with @. It is not a table column and does not permanently store data.

Declare and assign an integer

DECLARE @Age INT;
SET @Age = 21;
SELECT @Age AS StudentAge;

DECLARE creates the variable; INT specifies the type; SET assigns a value; SELECT displays it.

Expected result: StudentAge = 21

Initialize when declaring

DECLARE @CourseName VARCHAR(50) = 'Database Development';
SELECT @CourseName AS Course;

A variable can receive its initial value in the DECLARE statement.

Expected result: Course = Database Development

Change a variable

DECLARE @Score INT = 70;
SET @Score = @Score + 10;
SELECT @Score AS NewScore;

Read the current value (70), add 10, and store the new value (80).

Expected result: NewScore = 80

Common data types

TypeUseExample
INTWhole numbers15
DECIMAL(10,2)Exact numbers with two decimal places29.95
VARCHAR(50)Non-Unicode text, up to 50 characters'Alex'
NVARCHAR(50)Unicode textN'José'
DATECalendar date'2026-10-15'
BIT0, 1, or NULL1

SET versus SELECT assignment

DECLARE @Price DECIMAL(10,2);
SET @Price = 19.99;
SELECT @Price AS Price;

-- SELECT can also assign a variable:
SELECT @Price = 24.50;
SELECT @Price AS UpdatedPrice;

Both forms can assign values. SET is usually clearest for one explicit assignment. A SELECT @x = column query that returns several rows may overwrite the variable repeatedly; avoid assuming which row will be last without a deterministic approach.

Expected result: First 19.99; then 24.50

Variables begin as NULL

DECLARE @City VARCHAR(30);
SELECT @City AS City;

Without an initializer, a local variable has the value NULL, meaning no known value.

Expected result: City = NULL
Important: GO is a batch separator recognized by tools such as SSMS, not a T-SQL statement. A local variable declared before GO is unavailable afterward. Run each standalone example separately.

3. Expressions, comparisons, and NULL

Conditions are predicates that SQL Server evaluates as TRUE, FALSE, or UNKNOWN. An IF block executes only when the predicate is TRUE.

OperatorMeaningExample
=Equal to@x = 10
<>Not equal@x <> 10
>, <, >=, <=Compare values@x >= 70
ANDBoth conditions true@x >= 0 AND @x <= 100
OREither condition true@x < 0 OR @x > 100
NOTNegates a predicateNOT (@x = 0)
IS NULLTests for missing value@x IS NULL

Checking NULL correctly

DECLARE @Discount DECIMAL(5,2) = NULL;
IF @Discount IS NULL
    SELECT 'No discount supplied' AS Message;

Use IS NULL, not = NULL. Comparisons with NULL generally evaluate to UNKNOWN.

Expected result: No discount supplied

COALESCE supplies a default

DECLARE @Discount DECIMAL(5,2) = NULL;
SELECT COALESCE(@Discount, 0) AS Discount;

COALESCE returns the first non-NULL expression.

Expected result: Discount = 0

Arithmetic note: SQL Server uses +, -, *, /, and % (remainder). Integer division truncates the fractional part, so use decimal operands when fractions matter.

4. IF, ELSE, and BEGIN ... END

IF tests a condition. If true, the following statement executes; otherwise the optional ELSE statement executes. BEGIN ... END groups multiple statements into one block.

Simple IF

DECLARE @Score INT = 85;
IF @Score >= 70
    SELECT 'Pass' AS Result;

Because 85 is at least 70, the message is returned.

Expected result: Pass

IF / ELSE

DECLARE @Score INT = 62;
IF @Score >= 70
BEGIN
    SELECT 'Pass' AS Result;
END
ELSE
BEGIN
    SELECT 'Needs improvement' AS Result;
END;

Only one branch runs. With a score of 62, the ELSE branch runs.

Expected result: Needs improvement

Multiple decisions with ELSE IF

DECLARE @Score INT = 86;
IF @Score >= 90
    SELECT 'A' AS Grade;
ELSE IF @Score >= 80
    SELECT 'B' AS Grade;
ELSE IF @Score >= 70
    SELECT 'C' AS Grade;
ELSE
    SELECT 'Below C' AS Grade;

Conditions are tested from top to bottom. The first true branch wins. SQL Server uses ELSE IF, not Python’s elif.

Expected result: Grade = B

Two statements require a block

DECLARE @Stock INT = 0;
IF @Stock = 0
BEGIN
    SELECT 'Out of stock' AS Status;
    SELECT 'Order more copies' AS ActionNeeded;
END;

Without BEGIN ... END, only the immediately following statement belongs to the IF.

Expected result: Two result sets
IF versus CASE: IF controls which SQL statements execute. CASE is an expression used inside a query to produce a value for each row. CASE is not a replacement for multi-statement IF blocks.

CASE inside SELECT

SELECT CASE WHEN 82 >= 70 THEN 'Pass' ELSE 'Fail' END AS Result;

This expression returns one value within a SELECT statement.

Expected result: Pass

5. WHILE loops, counters, and stopping

SQL Server provides a WHILE loop. It repeats a statement or block while the condition is TRUE. There is no built-in T-SQL FOR loop.

Count from 1 to 5

DECLARE @Counter INT = 1;
WHILE @Counter <= 5
BEGIN
    SELECT @Counter AS CurrentNumber;
    SET @Counter = @Counter + 1;
END;

First the condition is checked. The number is displayed. The counter increases by one. After 5, it becomes 6, so the loop ends.

Expected result: Five separate result sets: 1, 2, 3, 4, 5

Count backward

DECLARE @Counter INT = 3;
WHILE @Counter >= 1
BEGIN
    SELECT @Counter AS Countdown;
    SET @Counter = @Counter - 1;
END;

Decreasing the counter moves toward the stopping condition.

Expected result: 3, 2, 1

Add the numbers from 1 to 4

DECLARE @N INT = 1;
DECLARE @Total INT = 0;
WHILE @N <= 4
BEGIN
    SET @Total = @Total + @N;
    SET @N = @N + 1;
END;
SELECT @Total AS SumOfNumbers;

The running total changes from 0 → 1 → 3 → 6 → 10.

Expected result: SumOfNumbers = 10

Trace the loop

Iteration@N before addition@Total after addition
111
223
336
4410

BREAK ends the loop

DECLARE @N INT = 1;
WHILE @N <= 10
BEGIN
    IF @N = 4 BREAK;
    SELECT @N AS Number;
    SET @N = @N + 1;
END;

The loop stops completely when @N reaches 4, before displaying it.

Expected result: 1, 2, 3

CONTINUE skips the rest of one iteration

DECLARE @N INT = 0;
WHILE @N < 5
BEGIN
    SET @N = @N + 1;
    IF @N = 3 CONTINUE;
    SELECT @N AS Number;
END;

The counter is incremented before CONTINUE. This prevents an endless loop when 3 is skipped.

Expected result: 1, 2, 4, 5
Infinite loop warning: Always check that the loop can eventually become false or reach BREAK. If you accidentally start a runaway query in SSMS, use the Cancel Executing Query command.
Database best practice: SQL is usually faster and clearer when you operate on whole sets of rows with SELECT, UPDATE, and aggregates. Use WHILE when sequential control flow is genuinely necessary, not automatically for every row.

6. Combining variables with database queries

The next examples use a small online bookstore dataset. Run the setup once in a scratch database where you are permitted to create temporary tables. The temporary table exists only for your current SQL Server session.

Create and populate sample data

CREATE TABLE #Books (
    BookID INT PRIMARY KEY,
    Title VARCHAR(60),
    Category VARCHAR(30),
    Price DECIMAL(10,2),
    Stock INT
);
INSERT INTO #Books (BookID, Title, Category, Price, Stock) VALUES
(1, 'Python Basics', 'Programming', 24.00, 8),
(2, 'SQL Essentials', 'Database', 32.50, 3),
(3, 'Web Design', 'Web', 19.00, 0),
(4, 'Advanced SQL', 'Database', 45.00, 5);
SELECT * FROM #Books;

Run this setup before the remaining examples in this section. Do not rerun CREATE TABLE in the same session without first dropping the temporary table.

Expected result: Four book rows

Store a value returned by a query

DECLARE @BookCount INT;
SELECT @BookCount = COUNT(*) FROM #Books;
SELECT @BookCount AS TotalBooks;

The aggregate returns one row, making it suitable for assigning one variable.

Expected result: TotalBooks = 4

Decide based on a database value

DECLARE @LowStockCount INT;
SELECT @LowStockCount = COUNT(*) FROM #Books WHERE Stock < 5;
IF @LowStockCount > 0
    SELECT 'Some books need attention' AS Alert;
ELSE
    SELECT 'Stock looks sufficient' AS Alert;

Two books have stock below 5 (SQL Essentials and Web Design), so the IF branch runs.

Expected result: Some books need attention

Use a variable as a filter

DECLARE @MaxPrice DECIMAL(10,2) = 30.00;
SELECT Title, Price FROM #Books WHERE Price <= @MaxPrice ORDER BY Price;

The variable makes the price limit easy to change without rewriting the WHERE condition.

Expected result: Web Design (19.00); Python Basics (24.00)

Loop over numbers, not book rows

DECLARE @Threshold INT = 0;
WHILE @Threshold <= 4
BEGIN
    SELECT @Threshold AS Threshold,
           COUNT(*) AS BooksAtOrBelowThreshold
    FROM #Books
    WHERE Stock <= @Threshold;
    SET @Threshold = @Threshold + 2;
END;

This repeats a summary for thresholds 0, 2, and 4. For one summary of all books, a set-based query is preferable.

Expected result: Counts: 1 at 0; 1 at 2; 2 at 4
Scope: A #Books temporary table survives across batches in the same connection, but local variables do not survive a GO batch separator. If you reconnect or close the session, recreate #Books.

7. Variables inside stored procedures

A stored procedure is a named collection of T-SQL statements saved in the database. A procedure may accept parameters such as @MinPrice. A parameter is supplied by the caller; a local variable is declared inside the procedure.

Create a simple procedure

CREATE OR ALTER PROCEDURE dbo.ShowPriceMessage
    @Price DECIMAL(10,2)
AS
BEGIN
    SET NOCOUNT ON;
    IF @Price >= 30
        SELECT 'Higher-priced book' AS PriceGroup;
    ELSE
        SELECT 'Lower-priced book' AS PriceGroup;
END;

Run this as its own batch in a database where you have CREATE PROCEDURE permission. CREATE OR ALTER PROCEDURE must start a batch; do not place ordinary statements before it in the same batch.

Expected result: Procedure created

Call the procedure

EXEC dbo.ShowPriceMessage @Price = 35.00;

The supplied parameter is 35.00, so the first branch executes.

Expected result: Higher-priced book

Procedure with a local variable

CREATE OR ALTER PROCEDURE dbo.ShowDiscountedPrice
    @Price DECIMAL(10,2),
    @DiscountPercent DECIMAL(5,2)
AS
BEGIN
    SET NOCOUNT ON;
    DECLARE @FinalPrice DECIMAL(10,2);
    SET @FinalPrice = @Price * (1 - @DiscountPercent / 100.0);
    SELECT @FinalPrice AS FinalPrice;
END;

Parameters are inputs. The local variable stores a calculated result. Create the procedure in its own batch, then execute it separately.

Call with named arguments

EXEC dbo.ShowDiscountedPrice @Price = 50.00, @DiscountPercent = 10.00;

A 10% discount on 50.00 produces 45.00.

Expected result: FinalPrice = 45.00
You do not need stored procedures to use variables, IF, or WHILE. Those constructs also work in an ordinary query batch. The procedure examples show how the same concepts are reused in database applications.

Messages versus results

DECLARE @Status VARCHAR(20) = 'Ready';
PRINT @Status;
SELECT @Status AS Status;

PRINT displays a message; SELECT produces a result set.

Debugging strategy: Run the smallest working portion first; inspect variable values with SELECT @Variable AS DebugValue; trace the condition manually; check the loop update; and then add one statement at a time.

11. Mini-project: Bookstore Inventory Assistant

Goal: Use variables, IF/ELSE, and WHILE together to check stock and calculate the cost of a small order. This project works without any permanent database tables.

  1. Set the number of copies available and the requested quantity.
  2. Check whether the order can be filled.
  3. Calculate the discounted price if the order is valid.
  4. Use WHILE to display a simple sequence of packing numbers.
Challenge

Complete mini-project solution

Write a T-SQL script for stock = 4, requested quantity = 3, unit price = 20, and discount = 10%. Show either an error or a total; if valid, show packing numbers 1 through 3.

Show worked solution and explanation
DECLARE @Stock INT = 4;
DECLARE @Requested INT = 3;
DECLARE @UnitPrice DECIMAL(10,2) = 20.00;
DECLARE @Discount DECIMAL(5,2) = 10.00;
DECLARE @OrderTotal DECIMAL(10,2);

IF @Requested <= 0 OR @Requested > @Stock
BEGIN
    SELECT 'Order cannot be filled' AS Status;
END
ELSE
BEGIN
    SET @OrderTotal = @Requested * @UnitPrice
        * (1 - @Discount / 100.0);
    SELECT 'Order accepted' AS Status, @OrderTotal AS OrderTotal;

    DECLARE @CopyNumber INT = 1;
    WHILE @CopyNumber <= @Requested
    BEGIN
        SELECT @CopyNumber AS PackingNumber;
        SET @CopyNumber = @CopyNumber + 1;
    END;
END;

The request is valid (3 <= 4). The total is 3 × 20 × 0.90 = 54.00. Packing numbers are 1, 2, and 3. Test again with @Requested = 5 to see the rejection branch.

Extension tasks

Modify the script to reject negative stock, apply no discount for quantities below 3, and report how many copies remain after the order. Predict the results before executing.
