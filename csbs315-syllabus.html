🖥️ Course Overview

This course covers key topics in programming language design and implementation. Students explore foundational principles — syntax, type systems, binding, scope, memory models, and paradigms — using C, C#, and Python as three distinct analytical lenses. By the end of the quarter, students evaluate each language's design decisions and the tradeoffs they represent. 

Minimum Passing Grade: C or higher

Prerequisites: Grade of "C" or higher in CSE 223. Admission into the BS Computer Science program is required for enrollment.

Note: Students cannot receive credit for both CSE 315 and CSBS 315.

🗺️ What You'll Learn

This course is built around a single guiding question: why do programming languages look and behave differently — even when they solve the same problems? You will not just learn syntax. You will learn to read language design as a series of deliberate decisions, each with tradeoffs.

Three languages serve as your analytical framework throughout. You will see the same concept — a variable declaration, an error handler, a memory model — in all three, and ask: what did each designer choose, what did they gain, and what did they give up?

C — The Foundation

› Explicit, low-level control

› Manual memory management

› Static typing, procedural only

› Why C influenced everything

C# — The Middle Ground

› OOP-first with type inference

› Managed memory via GC

› Nullable types, LINQ, delegates

› Safety + performance balance

Python — The Contrast

› Dynamic binding & duck typing

› Fully automatic memory

› Multi-paradigm by design

› Readability as a core value
🎯 Final Project — Week 12 Students deliver a 10-minute comparative evaluation of C, C#, and Python across three chosen design dimensions, supported by an 8–10 page written report with side-by-side code examples from all three languages.
🛤️ How the Course Unfolds

The course is organised into six units across twelve weeks. Each unit examines one dimension of language design — and each week compares how C, C#, and Python answered the same design question differently.

1

Unit 1 — Foundations of Language Design · Weeks 1–2

Week 1 · Why Programming Languages Exist  |  Week 2 · Syntax, Tokens & Grammars

Begin by asking: what problem do programming languages solve — and why are there so many of them? Week 1 covers language history, taxonomy (imperative, functional, declarative), and the first three-language comparison via Hello World. Week 2 dives into how source code becomes tokens, how grammars define valid programs, and why Python's indentation-based syntax is a different kind of design choice from C and C#'s brace-based model.

🔑 Key concepts:
· Language history and taxonomy  · Readability, writability, reliability
· Lexical analysis and tokenisation  · BNF / EBNF grammars
· Syntax diagrams and parse trees  · Abstract Syntax Trees (ASTs)

📝 Assignment 1 due Week 2: Write the BNF grammar for a simple if-statement in all three languages.
2

Unit 2 — Names, Variables & Scope · Weeks 3–4

Week 3 · Variables, Binding & Lifetime  |  Week 4 · Scope Rules & Symbol Tables

Week 3 examines what a variable actually is — name, type, value, address, lifetime — and when those attributes get bound. C requires explicit declarations; C# offers optional type inference via var; Python uses dynamic binding entirely. Week 4 covers how languages decide which variable a name refers to — static vs dynamic scoping, the LEGB rule in Python, four scope levels in C#, and the symbol tables compilers use to track all of this.

🔑 Key concepts:
· Binding times: static vs dynamic  · Stack vs heap allocation
· Static (lexical) vs dynamic scoping  · LEGB rule (Python)
· Block, method, class, namespace scope (C#)  · Shadowing & symbol tables

📝 Assignment 2 due Week 4: Trace the scope of 5 variables through a given program in all three languages.
3

Unit 3 — Type Systems · Weeks 5–6

Week 5 · Static vs Dynamic Typing  |  Week 6 · Primitive Types, Strings & Arrays

Week 5 draws a careful distinction between static/dynamic typing (when type checking happens) and strong/weak typing (what operations are permitted) — two independent dimensions students regularly confuse. Week 6 examines how the three languages represent and manipulate data: C's fixed-size primitives and null-terminated strings, C#'s immutable string class and nullable types, and Python's unified object model where everything — including integers — is an object.

🔑 Key concepts:
· Static vs dynamic typing  · Strong vs weak typing  · Duck typing
· Primitive types and fixed sizes (C)  · Nullable types with ? (C#)
· Python's unified object model  · Strings, arrays, and type coercion

📝 Midterm Exam — Week 6: Covers Units 1–3. Grammar writing, scope tracing, and type system analysis.
4

Unit 4 — Control Flow & Functions · Weeks 7–8

Week 7 · Control Structures & Error Handling  |  Week 8 · Functions & Parameter Passing

Week 7 compares how the three languages handle decisions and errors — C's return-code convention vs C# and Python's structured exception handling — and asks why two very different languages converged on the same error model. Week 8 examines how functions pass data: C's pointers for by-reference semantics, C#'s ref keyword and tuple returns, and Python's first-class functions and clean multiple-return syntax.

🔑 Key concepts:
· Conditionals, loops, switch/match design  · goto and why it's avoided
· Structured exception handling vs return codes  · try/catch/finally
· Pass by value vs pass by reference  · First-class functions
· C# delegates, Func<T>, lambdas  · Recursion and stack frames

📝 Assignment 3 due Week 8: Implement binary search in all three languages — compare function signatures, parameter passing, and return values.
5

Unit 5 — Memory Management · Weeks 9–10

Week 9 · Manual Memory in C  |  Week 10 · Garbage Collection & Memory Models

Week 9 examines C's manual memory model: malloc, free, memory leaks, dangling pointers, and buffer overflows — and asks what it means to give programmers this level of control. Week 10 compares the garbage collection strategies of C# (generational, .NET CLR) and Python (reference counting + cyclic GC), examines the performance cost of automation, and asks why C is still chosen over both in embedded systems and game engines.

🔑 Key concepts:
· Stack vs heap · malloc / free · Memory leaks & dangling pointers
· Reference counting (Python) · Generational GC (C#) · Mark-and-sweep
· IDisposable and using (C#) · GC performance tradeoffs

📝 Assignment 4 due Week 10: Compare memory models across all three languages — who manages memory, GC strategy, failure modes, and performance tradeoffs.
6

Unit 6 — Paradigms & Final Evaluation · Weeks 11–12

Week 11 · Paradigm Deep Dive  |  Week 12 · Final Presentations & Course Synthesis

Week 11 examines C as the gold standard of procedural programming, C# as OOP-first with LINQ, and Python's multi-paradigm flexibility — then asks why some languages commit to one paradigm and others support many. Week 12 is presentation day: each student delivers a 10-minute comparative evaluation of all three languages on three chosen design dimensions, followed by a class discussion on the evolution arc from C to C# to Python and where all three are used together in industry today.

🎯 Final Project: 8–10 page comparative evaluation of C, C#, and Python. Sections: syntax design, type system, memory model, paradigm support, and error handling. Each section must include side-by-side code examples from all three languages. Live 10-minute presentation in Week 12.
